# 故障诊断 Agent 后续改进计划

> 状态：待实施  
> 制定日期：2026-07-31  
> 适用范围：故障码知识查询链路  

## 1. 背景

当前故障诊断 Agent 已能：

- 对明确的故障码问题走确定性规划；
- 在 Agent 绑定的知识库中精确检索故障码；
- 调用大模型整理回答，并校验回答中的故障码和证据引用。

现阶段的主要问题是：知识库已经成功返回原因和处理方法，但当大模型调用异常、返回空内容或回答未通过安全校验时，降级逻辑只返回“已进行知识查询”的说明，没有输出已经取得的知识正文。

此外，纯故障码查询没有执行设备遥测，却使用了“确定性诊断事实”“本次遥测范围”等诊断模板，容易让用户误解。

## 2. 改进目标

本轮只解决以下问题：

1. 只要知识库精确命中，故障码查询就必须返回可用的原因、处理建议和来源。
2. 大模型作为可选的表达增强，不再成为故障码回答成功与否的必要条件。
3. 区分“故障码知识查询”和“设备遥测诊断”的输出文案。
4. 能从日志中判断回答为何进入降级路径。
5. 用自动化测试覆盖成功和降级场景。

## 3. 暂不处理的内容

为避免过度设计，本轮不做：

- 不新增工作流或 Agent 编排框架；
- 不修改数据库表结构；
- 不重做知识库切片和入库流程；
- 不引入新的向量检索或重排序方案；
- 不重构现有遥测诊断编排器和证据链；
- 不调整前端交互形式；
- 不追求一次覆盖所有厂商的故障码格式。

## 4. 实施计划

### 阶段一：保证降级答案完整

优先级：P0

1. 为纯故障码查询增加确定性回答渲染。
2. 根据 `FaultKnowledgeResult` 的状态分别处理：
   - `MATCHED`：输出故障码、知识正文和来源；
   - `NOT_FOUND`：明确说明已查询但未找到匹配内容；
   - `FAILED`：明确说明知识查询失败，建议稍后重试。
3. 大模型回答生成成功且通过安全校验时，可以使用模型整理后的答案。
4. 模型异常、空回答或安全校验失败时，直接返回确定性答案，不丢失知识正文。
5. 纯知识查询使用“故障码知识查询结果”模板，不再展示“诊断状态：未执行设备遥测诊断”等大段诊断字段。
6. 保留一句简短边界说明：本次仅查询故障手册，未读取设备遥测数据。
7. 第一版直接复用已精确命中的证据内容并做轻量排版，不新增通用故障手册解析器。

预期输出示例：

```text
故障码知识查询：F07561

含义：驱动编码器多圈线数不是二的幂次方。

原因：p0421 中的多圈分辨率必须是二的幂次方。

处理建议：
1. 检查参数设定 p0421、p0404.1 和 r0458.5。
2. 必要时升级编码器模块固件。

说明：本次仅查询故障手册，未读取设备遥测数据。
来源：S120_故障手册.pdf
```

### 阶段二：补齐日志和测试

优先级：P0

1. 回答生成进入降级路径时记录原因：
   - `MODEL_EXCEPTION`
   - `EMPTY_MODEL_ANSWER`
   - `SAFETY_VALIDATION_REJECTED`
2. 日志记录 `requestId`、任务类型、故障码、耗时和降级原因，不记录 API Key 和完整知识正文。
3. 增加以下自动化测试：
   - 知识命中且模型回答正常；
   - 模型调用异常时仍返回知识正文；
   - 模型返回空内容时仍返回知识正文；
   - 安全校验失败时仍返回知识正文；
   - `NOT_FOUND` 和 `FAILED` 不被误判为已命中；
   - 纯故障码查询不输出设备遥测诊断模板；
   - 回答始终包含可追溯的文档来源。

### 阶段三：小范围完善确定性路由

优先级：P1

在阶段一和阶段二稳定后，再小范围补充确定性路由边界：

1. 支持用户只输入一个明确故障码，例如 `F07561`。
2. 保留多故障码查询能力。
3. 包含设备、逆变器、时间范围或明确遥测诊断要求的问题，继续交给模型规划。
4. 模糊问题和上下文追问继续使用现有模型规划，不尝试用大量正则覆盖自然语言。
5. 服务端继续负责故障码格式、任务类型、时间范围和 Agent 知识库权限校验。

本阶段不要求立即切换 JSON Schema；只有在当前模型供应商确认兼容后再单独评估。

## 5. 建议修改范围

预计主要涉及：

- `FaultDiagnosisChatService`：区分知识查询与遥测诊断的回答流程；
- `FaultAnswerGenerator`：保持为可选表达增强；
- `FaultAnswerSafetyValidator`：为降级日志提供明确结果；
- `FaultRequestPlanner`：补充少量高置信度路由边界；
- 对应的故障诊断单元测试。

暂不修改知识库表、遥测表和前端代码。

## 6. 验收标准

以下条件全部满足后视为本轮完成：

1. 输入“F07561 是什么原因？如何解决？”时，回答包含原因、处理建议和来源。
2. 人为模拟模型不可用时，仍能返回同样可用的知识答案。
3. 纯故障码查询不会声称已经执行遥测诊断，也不会暗示设备当前一定发生该故障。
4. 知识未找到和知识查询失败有不同提示。
5. 日志可以明确识别是否发生模型异常、空回答或安全校验拒绝。
6. 复合遥测诊断请求仍进入原有确定性诊断编排器。
7. Agent 未绑定的知识库不能被请求参数或模型输出绕过。
8. 相关自动化测试全部通过，并完成一次真实 SSE 请求验证。

## 7. 实施顺序

建议按以下顺序提交，便于验证和回滚：

1. 完整的确定性知识回答和状态区分；
2. 模型失败时的降级逻辑；
3. 日志与自动化测试；
4. 小范围完善确定性路由；
5. 构建镜像并进行 SSE 端到端验证。

如果阶段一上线后已经满足实际使用需求，可以先观察运行效果，再决定是否实施阶段三。
